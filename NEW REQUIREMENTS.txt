PROJECT PROMPT FOR LOCAL LLM

Project name: KazaALKIS

Objective:
Create a Windows-based automation project that reads a Greek Kazamias-style database and sends daily WhatsApp notifications to selected contacts, including myself. The notification shall include today’s Greek name days, relevant Kazamias quotes, saints, feast day notes, holidays, fasting notes, and any additional structured information available in the local Kazamias database.

Main Requirements:

1. The project shall run locally on Windows.
2. All project files, Python environments, models, logs, databases, and tools shall be stored under:
   E:\AI\Kazamias_Daily_Herald
   Do not install or store project dependencies on C: unless technically unavoidable.
3. The system shall ask the user for configuration during first setup:

   * Kazamias database file path
   * WhatsApp provider option
   * Contact list file path
   * Preferred sending time
   * Preferred language: Greek, English, or bilingual
   * Message tone: formal, friendly, traditional, humorous
4. Supported Kazamias data formats:

   * SQLite database
   * CSV
   * Excel
   * JSON
   * Markdown/text import if structured parsing is possible
5. The system shall normalize the data into a local SQLite database with tables such as:

   * calendar_days
   * name_days
   * saints
   * quotes
   * holidays
   * fasting_notes
   * moon_calendar
   * source_references
   * contacts
   * message_logs
6. The daily message shall include:

   * Date
   * Greek Orthodox name day names
   * “Χρόνια πολλά” greeting
   * Kazamias quote of the day
   * Saint/feast day information where available
   * Optional holiday or fasting note
   * Optional “on this day” item if available
7. The system shall avoid duplicate messages on the same day unless manually forced.
8. The system shall log all messages sent, failed, skipped, or retried.
9. The system shall include privacy controls:

   * Store API keys in a .env file
   * Do not hard-code credentials
   * Do not expose contact numbers in logs except masked form
10. WhatsApp delivery options:
    Preferred:

* WhatsApp Business Cloud API
  Alternative:
* Twilio WhatsApp API
  Fallback:
* Generate message text only for manual copy/paste

11. Do not use fragile WhatsApp Web automation as the main method unless the user explicitly chooses “experimental mode”.
12. Include a PowerShell launcher with menu options:

* Setup project
* Import Kazamias database
* Preview today’s message
* Send today’s message
* Send test message
* Edit contacts
* View logs
* Export logs to Excel
* Schedule daily task

13. Include a simple local dashboard:

* Today’s message preview
* Contacts summary

* Missing database fields
* Data quality warnings

14. Include export options:

* Daily message to TXT
* Logs to CSV/XLSX
* Monthly name day calendar to Excel

15. Include robust error handling:

* Missing database
* Missing today’s record
* Invalid contact number
* API failure
* Duplicate sending attempt
* Network unavailable

16. Provide full folder structure, source code, setup instructions, and PowerShell commands.
17. Provide comments in the code.

19. Provide sample database schema and sample test records.
20. Validate that all assumptions are clearly listed before generating the final implementation.

17. Storage and Installation Requirements

IMPORTANT:
All AI models, embeddings, vector databases, caches, dependencies, tools, virtual environments, temporary files, logs, outputs, and related resources must be installed, downloaded, stored, and executed from the E:\AI directory structure and NOT on the C: drive.

The system must be designed assuming:
- C: drive space is limited
- E: drive is the dedicated AI workspace and storage location

Required behaviour:
- All Python virtual environments should default to:
  E:\AI\venvs\

- All model downloads should default to:
  E:\AI\models\

- All Ollama/local LLM model storage should default to:
  E:\AI\models\ollama\

- All cache directories should default to:
  E:\AI\cache\

- All logs should default to:
  E:\AI\logs\

- All exports and reports should default to:
  E:\AI\outputs\

- All temporary working files should default to:
  E:\AI\tmp\

- All cloned repositories and projects should default to:
  E:\AI\projects\

- All vector databases or embeddings should default to:
  E:\AI\vectorstore\

- All PowerShell scripts should support configurable root paths.

The application must:
- Avoid writing large files to C:
- Avoid storing models under user profile directories when possible
- Allow environment variables to override paths
- Centralize path configuration in one configuration file

Recommended environment variables:
- AI_ROOT=E:\AI
- AI_MODELS=E:\AI\models
- AI_CACHE=E:\AI\cache
- AI_OUTPUTS=E:\AI\outputs
- AI_VENVS=E:\AI\venvs

PowerShell launcher requirements:
- Validate E:\AI exists
- Create missing subfolders automatically
- Display storage usage and free space
- Warn user if C: drive is being used unexpectedly

Recommended folder structure:

E:\AI\
│
├── models\
├── cache\
├── outputs\
├── logs\
├── tmp\
├── venvs\
├── vectorstore\
├── projects\
├── shared\
└── tools\

The generated project must use configurable path management and avoid hardcoded user-profile paths.

All installation instructions, requirements, and scripts must assume E:\AI as the primary AI workspace root.
